# Disabled local Codex bridge preparation

Status: static preview remains disconnected. A generic stdio transport, process factory, coordinator, protected loopback server and separate streaming/approval UI are now implemented and mock-tested. There is no startup command or activation wiring to the existing preview. No app-server, authentication call or model turn was launched. Activation is blocked pending explicit action-time confirmation of the broad Mac file scope. The earlier folder-only/no-tools prerequisite is superseded by the requested scope; no read-confinement guarantee is required or claimed.

## Boundary and policy

Use a separately launched Node bridge binding only 127.0.0.1 on a dedicated port; serve its own trusted UI on that same origin. Preserve the existing static preview. Do not open CORS, proxy arbitrary methods, accept browser-provided executable paths or cwd/config overrides. Exact Host/Origin and Fetch Metadata checks apply to every mutation. A one-time same-origin pairing exchange creates a random process-lifetime session value, held in UI memory and passed in a custom header. No hardcoded secret, URL bearer token, localStorage credential, cache or logging. No third-party scripts; restrictive CSP, bounded bodies, content-type checks and noncacheable responses are required. Pairing assumes a trusted browser origin, not protection against a malicious local process. Revocation invalidates the value; disconnect interrupts turns, rejects pending approvals and closes the process. Bootstrap/pairing needs adversarial integration tests before use.

Confirm the selected folder by realpath at activation; reject root/home, symlink escapes and unexpected mount changes. Team/role identity maps to distinct ephemeral threads in process memory. One active turn globally initially; role switching never retargets an active request. Conflicting file writers remain serialized. Imported text is only reviewed role context; it cannot grant capabilities. Personal scope, prompts, thread IDs and conversations stay outside this tracked package. No global Codex config or permission profile is changed automatically.

Proposed native settings: approvalsReviewer=user, approvalPolicy=untrusted, thread sandbox=read-only initially; turn sandboxPolicy={type:readOnly,networkAccess:false}; explicit cwd/runtimeWorkspaceRoots point at the confirmed folder, environments=[], allowProviderModelFallback=false. These fields are present in the inspected schema; their runtime enforcement is not yet tested. cwd/roots are not demonstrated read confinement. Read-only blocks ordinary writes but does not guarantee every command prompts. Switching to workspaceWrite allows ordinary in-sandbox changes that may bypass approval; do not enable it merely to make edits work. Native trust rules and inherited tools/hooks/MCP/plugins must be inspected using supported runtime interfaces, without exposing secrets. A restrictive, independently verified OS boundary or documented permission profile is needed if reads must stay inside the folder. Safe staged patches or a constrained execution broker may be necessary to guarantee approval for every change/command. Prompts alone do not enforce this.

The user must approve the concrete folder, residual read scope, permitted command/change semantics, model data exposure and any persistent permission/config changes. Whole-Mac access, arbitrary commands, network tool access and persistent approval grants are excluded. Official runtime internal auth/config reads and model-service network traffic remain necessary and distinct from model file access. No blanket read confinement claim is made.

## Protocol mapping inspected locally

Source: locally generated public Codex 0.159.0 schema. No live runtime behavior demonstrated.

- ClientRequest.json: initialize, account/read, account/rateLimits/read, model/list, thread/start, turn/start, turn/interrupt.
- v2 aggregate definitions GetAccountParams/GetAccountResponse: account/read with refreshToken=false; accept only account.type=chatgpt. Reject apiKey, amazonBedrock, null or unknown. Never implement account/login/start or token refresh callbacks; official Codex owns authentication. Do not display account email or token fields.
- GetAccountRateLimitsResponse: require ordinaryUsageAllowed=true; null/absent is unknown, not available. Never consume reset credits or buy/fallback. Recheck account/usage before turns and invalidate on account updates. Actual included-usage accounting still needs verification.
- ModelListParams/Response: discover nonhidden account models, paginate nextCursor, permit only exact returned model IDs. No invented or silently substituted model. Account-specific availability is verified at activation.
- ThreadStartParams: cwd, runtimeWorkspaceRoots, approvalPolicy, approvalsReviewer, sandbox, ephemeral, allowProviderModelFallback. TurnStartParams: threadId, input, cwd, sandboxPolicy. TurnInterruptParams requires threadId and turnId. RPC results and streamed state must be bounded and validated; timeout/error does not equal completion.
- ServerRequest.json: item/commandExecution/requestApproval and item/fileChange/requestApproval use {decision:accept|decline|cancel}. The guard rejects acceptForSession and policy amendments. All other request types fail closed initially, including permissions, tool calls, legacy approvals, MCP elicitation and token refresh. Appropriate protocol error plus turn interruption is required for unsupported requests.

2. Dependency-injected stdio JSON-RPC transport: no shell, fixed trusted executable, controlled environment, bounded line buffer/queue, correlation IDs, initialize handshake, close/error/timeout handling. Unit tests use a fake child, not Codex.
3. Deny approvals on browser heartbeat loss and shutdown. Tests simulate malformed frames, duplicate/late IDs, timeout, crash, switch, cancellation and account changes.
4. Separate same-origin bridge server and plain-text approval UI: display exact command/cwd/requested permissions or patch, allow once/deny/cancel only; no remember option. Bind approval to session/thread/turn/item/request IDs. Mock HTTP tests cover cross-origin, Host spoofing, missing token, expired sessions, replay, reconnect, body bounds, unknown methods and disconnect races. Existing CSP connect-src none stays until this separate UI is approved.
5. Review concrete scope, OS enforcement and inherited configuration; adversarial tests of attempted outside-folder reads/writes, symlinks, shell/network/tool escapes, and approval coverage. Only then explicit Enable may spawn official Codex and read supported account/model/usage endpoints. Consent for these checks precedes activation; models run only afterward. Keep the bridge disabled if any gate is unknown.

Prepared tests prove guard behavior with fabricated values only. They do not prove session bootstrap, OS isolation, runtime policy enforcement, subscription billing guarantees, process lifecycle or UI approval coverage. No executable adapter is supplied because those boundaries are unresolved.

## Current implementation and proposed startup policy

The process factory (not invoked) would run an explicitly configured, absolute, trusted local Codex executable with argv `app-server --stdio -c approval_policy="untrusted" -c sandbox_mode="read-only"`, shell=false, and the user-selected realpath working directory. It passes only HOME/PATH/TMPDIR/LANG/LC_ALL from the host environment, not API-key or custom-provider environment variables. Official Codex reads its own login/configuration. No reusable credential is read by Rolequilt. No global config edit, TCC/Full Disk Access change, sudo, permission-profile installation or persistent daemon is supplied.

Threads verify the runtime returned untrusted/user/readOnly policy, matching cwd and OpenAI model provider/model before sending prompts. Turns explicitly retain those policies with networkAccess=false. This permits broad filesystem reads subject to the native sandbox and macOS protected permissions; cwd is context, not a whole-Mac read allowlist. Ordinary writes are restricted. Requested changes or escalated commands can arrive as native approval requests; trusted reads/commands may not prompt. Allow once grants the presented action, including residual requested permissions shown in the UI; persistent grants and unknown server request methods are rejected. Read-only plus native one-shot escalation is the conservative first release; broad ordinary writing is not enabled. Existing runtime rules/hooks/plugins may influence behavior and still need activation-time review. These policies are schema-compatible, not yet demonstrated with a live runtime.

Account and included-usage checks precede each turn. Only chatgpt mode and ordinaryUsageAllowed=true proceed; unknown/null is blocked. Model choices come from paginated nonhidden model/list responses; IDs map to their returned model values. Provider fallback=false on new threads; no API login/reset-credit/billing calls exist. Changes to account/usage disconnect and require a new process/session.

The bridge server forcibly binds 127.0.0.1. The separate UI pairs once and polls bounded event history every two seconds using an in-memory custom-header session. Heartbeat loss after 15 seconds invalidates pairing and disconnects the engine. Pending approval timeout is 60 seconds; cancellation completion timeout is 15 seconds; RPC timeout is 15 seconds. Disconnect cancels pending approvals, closes stdin, sends SIGTERM and schedules SIGKILL. Concurrency is one; role threads are ephemeral and isolated in process memory. There is no transcript storage in the public repo or browser localStorage. The existing static preview is untouched.

Mock tests cover subprocess frames/errors/timeouts, per-role isolation, actual approval callback response shapes, cancellation request, subscription rejection, no-confirmation blocking, unknown request disconnection and HTTP session/Origin protection. Remaining integration work: explicit startup orchestration from approved private scope configuration, live protocol compatibility, native approval behavior, browser-rendered QA, request payload/patch coverage, reconnect UX and malicious/local-process threat testing. Native policy restrictions or absent usage fields may intentionally block activation. No live-read/write/model/billing guarantee is inferred from mocks.

File-change approval additionally requires bounded matching item/started fileChange details (paths/diffs) to have arrived; absent details deny and disconnect. Commands require displayable command and cwd. This prevents a blind Allow once button when native request params omit the patch. Live event ordering remains unverified and may fail closed.
