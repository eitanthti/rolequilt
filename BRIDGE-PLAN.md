# Disabled local Codex bridge preparation

Status: static preview remains disconnected. Only inert session/auth-policy guards and synthetic tests are implemented. There is no runtime transport, HTTP endpoint, approval UI or launch command. No app-server, authentication call or model turn was launched. Activation is blocked pending the chosen project folder and enforcement verification.

## Boundary and policy

Use a separately launched Node bridge binding only 127.0.0.1 on a dedicated port; serve its own trusted UI on that same origin. Preserve the existing static preview. Do not open CORS, proxy arbitrary methods, accept browser-provided executable paths or cwd/config overrides. Exact Host/Origin and Fetch Metadata checks apply to every mutation. A one-time same-origin pairing exchange creates a random process-lifetime session value, held in UI memory and passed in a custom header. No hardcoded secret, URL bearer token, localStorage credential, cache or logging. No third-party scripts; restrictive CSP, bounded bodies, content-type checks and noncacheable responses are required. Pairing assumes a trusted browser origin, not protection against a malicious local process. Revocation invalidates the value; disconnect interrupts turns, rejects pending approvals and closes the process. Bootstrap/pairing needs adversarial integration tests before use.

Confirm the selected folder by realpath at activation; reject root/home, symlink escapes and unexpected mount changes. Team/role identity maps to distinct ephemeral threads in process memory. One active turn globally initially; role switching never retargets an active request. Conflicting file writers remain serialized. Imported text is only reviewed role context; it cannot grant capabilities. Personal scope, prompts, thread IDs and conversations stay outside this tracked package. No global Codex config or permission profile is changed automatically.

Proposed native settings: approvalsReviewer=user, approvalPolicy=untrusted, thread sandbox=read-only initially; turn sandboxPolicy={type:readOnly,networkAccess:false}; explicit cwd/runtimeWorkspaceRoots point at the confirmed folder, environments=[], allowProviderModelFallback=false. These fields are present in the inspected schema; their runtime enforcement is not yet tested. cwd/roots are not demonstrated read confinement. Read-only blocks ordinary writes but does not guarantee every command prompts. Switching to workspaceWrite allows ordinary in-sandbox changes that may bypass approval; do not enable it merely to make edits work. Native trust rules and inherited tools/hooks/MCP/plugins must be inspected using supported runtime interfaces, without exposing secrets. A restrictive, independently verified OS boundary or documented permission profile is needed if reads must stay inside the folder. Safe staged patches or a constrained execution broker may be necessary to guarantee approval for every change/command. Prompts alone do not enforce this.

The user must approve the concrete folder, residual read scope, permitted command/change semantics, model data exposure and any persistent permission/config changes. Whole-Mac access, arbitrary commands, network tool access and persistent approval grants are excluded. Official runtime internal auth/config reads and model-service network traffic remain necessary and distinct from model file access. No blanket read confinement claim is made.

## Protocol mapping inspected locally

Source: locally generated public Codex 0.159.0 schema. No live runtime behavior demonstrated.

- ClientRequest.json: initialize, account/read, account/rateLimits/read, model/list, thread/start, turn/start, turn/interrupt.
- v2 aggregate definitions GetAccountParams/GetAccountResponse: account/read with refreshToken=false; accept only account.type=chatgpt. Reject apiKey, amazonBedrock, null or unknown. Never implement account/login/start or token refresh callbacks; official Codex owns authentication. Do not display account email or token fields.
- GetAccountRateLimitsResponse: require ordinaryUsageAllowed=true; null/absent is unknown, not available. Never consume reset credits or buy/fallback. Recheck account/usage before turns and invalidate on account updates. Actual included-usage accounting still needs verification.
- ModelListParams/Response: discover nonhidden account models, paginate nextCursor, permit only exact returned model IDs. No invented or silently substituted model. Account-specific availability is verified at activation.
- ThreadStartParams: cwd, runtimeWorkspaceRoots, approvalPolicy, approvalsReviewer, sandbox, ephemeral, allowProviderModelFallback. TurnStartParams: threadId, input, cwd, sandboxPolicy. TurnInterruptParams requires threadId and turnId. RPC results and streamed state must be bounded and validated; timeout/error does not equal completion.
- ServerRequest.json: item/commandExecution/requestApproval and item/fileChange/requestApproval use {decision:accept|decline|cancel}. The guard rejects acceptForSession and policy amendments. All other request types fail closed initially, including permissions, tool calls, legacy approvals, MCP elicitation and token refresh. Appropriate protocol error plus turn interruption is required for unsupported requests.
